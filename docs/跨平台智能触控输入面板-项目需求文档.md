## 1. 项目概述

### 1.1 项目名称

跨平台智能触控输入面板 —— Smart Touch Panel（简称 STP）

### 1.2 项目愿景

打造一款**轻量级、高定制、跨平台**的虚拟输入面板系统，让任何平板设备无需安装任何 App，通过浏览器即可变身为用户专属的输入控制台。

### 1.3 核心差异化优势

| 维度 | 现有方案 (Touch Portal / Deckboard) | 本题方案 |
|------|--------------------------------------|----------|
| 平板端安装 | ❌ 必须安装原生 App | ✅ 浏览器零安装，开网页即用 |
| iOS 支持 | ❌ Deckboard 不支持 iOS | ✅ 浏览器即可访问 |
| 跨设备同步 | 需登录账号 | ✅ Profile 文件即传即用 |
| PC 端编辑 | 独立编辑器 | ✅ 浏览器即编辑器，PC/平板均可编辑 |

## 3. 核心价值主张

### 3.1 即插即用

- 客户端（平板/手机）：无需安装任何 App，打开浏览器访问网址即可使用
- Host 端（PC/Mac）：提供完整的安装程序（macOS .app bundle），可注册为系统服务、开机自启

### 3.2 形态自由

不局限于标准键盘，允许用户为任何特定任务创建并保存完全自定义的按键布局。按键的位置、大小、颜色、功能均可自由定义。

### 3.3 跨设备习惯同步

用户的个性化布局配置（Profile）以 JSON 文件形式跨设备迁移。

### 3.4 智能上下文感知

PC 端服务能识别当前激活的软件，并**自动切换**到对应的键盘布局。

## 8. 关键技术实现方案

### 8.1 输入模拟引擎

macOS: `CGEventCreateKeyboardEvent` + `CGEventPost(kCGHIDEventTap)`

支持的按键：字母(A-Z)、数字(0-9)、功能键(F1-F12)、方向键、修饰键(⌘⌥⌃⇧)、组合键(COMMAND+T 等)

> **注意**：macOS Catalina+ 需要**辅助功能权限**（System Settings → Privacy → Accessibility）。

### 8.2 前台窗口监控

`NSWorkspace.sharedWorkspace().notificationCenter` 监听 `NSWorkspaceDidActivateApplicationNotification`。AppObserver(NSObject) 子类，回调通过 `asyncio.run_coroutine_threadsafe` 广播 WebSocket。

### 8.3 打包与分发

- py2app → .app bundle (LSUIElement=true, 菜单栏应用, 无 Dock 图标)
- cron @reboot + keep_alive.sh 守护

### 8.4 前端渲染

- Vanilla JS，绝对定位渲染
- CSS transform 动画（按键反馈）
- 触摸事件直达 WebSocket

## 9. 数据模型 (v2.0 — 无限画布模型)

### 9.1 Profile 结构 <a id="§9.1"></a>

```json
{
  "profileName": "Default",
  "version": "1.0",
  "device": "iPad 11\"",
  "deviceWidth": 834,
  "deviceHeight": 1210,
  "cellSize": 60,
  "canvasX": 0,
  "canvasY": 0,
  "defaultSound": "click",
  "windowRules": [
    {"bundle_id": "com.apple.Safari", "page": "browsing"}
  ],
  "pages": [{
    "id": "main",
    "label": "Main",
    "keys": [{
      "id": "k1",
      "label": "A",
      "col": 0,
      "row": 0,
      "w": 1,
      "h": 1,
      "action": "key",
      "value": "A",
      "color": "#0f3460",
      "sound": ""
    }]
  }]
}
```

### 9.2 字段说明 <a id="§9.2"></a>

| 字段 | 类型 | 说明 |
|------|------|------|
| `device` | string | 设备预设名称 |
| `deviceWidth/deviceHeight` | int | 设备 CSS 像素尺寸（决定视口框比例） |
| `cellSize` | int | 缩放级别（每格 px），范围 20-200，默认 60 |
| `canvasX/canvasY` | float | 画布偏移（grid cell 单位），控制框内可见区域 |
| `defaultSound` | string | 全局默认音效（none/click/soft/mechanical/deep） |
| `windowRules` | array | 窗口匹配规则（bundle_id → page） |
| `pages[].keys[].col/row` | float | 按钮在无限画布上的格子坐标 |
| `pages[].keys[].w/h` | int | 按钮占用的格子数（≥1） |
| `pages[].keys[].action` | string | 操作类型：key（按键）或 text（文本输入） |
| `pages[].keys[].value` | string | 按键值（如 "A", "TAB", "COMMAND+T"） |
| `pages[].keys[].sound` | string | 按钮级音效（空字符串 = 继承全局） |
| `pages[].keys[].color` | string | 按钮背景色 (CSS color) |
| `windowRules[].bundle_id` | string | macOS Bundle Identifier，用于匹配前台 App |
| `windowRules[].page` | string | 匹配时自动切换到目标 page ID |

### 9.3 设备预设 <a id="§9.3"></a>

| 名称 | 宽高比 | CSS 尺寸 | 覆盖设备 |
|------|--------|----------|----------|
| iPad 4:3 | ~1.33 | 1024×1366 | Pro 13", Air 13", legacy |
| iPad 11" | ~1.45 | 834×1210 | Pro 11", Air 11", iPad 10 |
| iPad mini | ~1.52 | 744×1133 | iPad mini 6/7 |
| Android 16:10 | 1.6 | 1280×800 | Galaxy Tab S 系列 |

同比例设备在编辑器中共用一个框。默认设备 = iPad 11"。

### 9.4 无限画布模型 <a id="§9.4"></a>

- 按钮存储在无限画布的 `(col, row)` 坐标上，无边界限制
- 设备框 = iPad 屏幕的观察窗口，固定在编辑器中央
- iPad 渲染 = 框内可见按钮，用 `(col - canvasX) * cellSize * scale` 映射到像素
- iPad 端 CSS: `position: absolute` 绝对定位，`align-content: start` 不拉伸填满
- 编辑器显示比例与 iPad 完全一致（所见即所得）
- Zoom = 改变 cellSize，框大小不变
